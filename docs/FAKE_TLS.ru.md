# Fake TLS

[English](FAKE_TLS.md) · **Русский**

Fake TLS нужен, когда вы запускаете `tg-proxy` как общий или публичный MTProto-прокси на сервере. Самые первые байты клиента выглядят как рукопожатие TLS 1.3 с обычным сайтом; отличить их может только тот, кто знает секрет.

```bash
tg-proxy --host 0.0.0.0 --mtproto-port 443 --port 0 \
         --fake-tls-domain example.com --secret 00112233445566778899aabbccddeeff
```

Прокси напечатает ссылку `ee`:

```
tg://proxy?server=IP.ВАШЕГО.СЕРВЕРА&port=443&secret=ee<секрет><hex от "example.com">
```

## Как он прячется

1. Клиент шлёт ClientHello, в поле random которого лежит HMAC от вашего секрета (плюс время). `tg-proxy` проверяет его и отвечает правдоподобным серверным ответом TLS 1.3, тоже подписанным секретом.
2. **Всё, что проверку не прошло, пересылается на настоящий `example.com`** байт в байт, включая собственный ClientHello зонда. Сканер или активный зонд цензора просто общается с живым сайтом.
3. **Повтор** настоящего ClientHello считается зондом: записать рукопожатие клиента и проиграть его заново, чтобы выдать прокси, не получится. (Кроме того, hello принимается только в пределах ±120 с от времени сервера.)
4. Не-TLS трафик на этом порту получает редирект, как от обычного веб-сервера. Рукопожатие, прошедшее TLS-проверку, но с неверным секретом обфускации, молча игнорируется.

## Выбор домена

Возьмите настоящий популярный HTTPS-сайт, до которого **достаёт ваш сервер** и который не заблокирован у ваших пользователей. Он не обязан быть вашим и не обязан указывать на ваш сервер: это лишь имя, под которое маскируется соединение, и адрес, куда пересылаются зонды. Следите за точным временем на сервере (NTP).

## За nginx (делить порт 443 с настоящим сайтом)

Если на сервере на 443 уже живёт сайт, пусть nginx разводит трафик по SNI и передаёт трафик прокси в `tg-proxy` через PROXY protocol, чтобы сохранились адреса клиентов:

```nginx
stream {
    upstream mtproto { server 127.0.0.1:8446; }
    upstream website { server 127.0.0.1:8443; }   # ваш настоящий HTTPS-сайт

    map $ssl_preread_server_name $backend {
        example.com  mtproto;      # это --fake-tls-domain
        default      website;
    }

    server {
        listen 443;
        ssl_preread on;
        proxy_pass $backend;
        proxy_protocol on;         # tg-proxy нужен --proxy-protocol; ваш сайт тоже должен его принимать
    }
}
```

```bash
tg-proxy --host 127.0.0.1 --mtproto-port 8446 --port 0 \
         --fake-tls-domain example.com --proxy-protocol --secret <32 hex-символа>
```

Ссылка тогда указывает на порт **443**, а в `server=` стоит ваш домен или IP.

## Примечания

- Без `--fake-tls-domain` прокси говорит на обычном обфусцированном MTProto (ссылка `dd`): подходит для себя или доверенной локальной сети, но в открытом Интернете распознаётся проще.
- Не оставляйте секрет в общедоступных местах и публичных логах. `tg-proxy` печатает ссылки только в консоль, а созданный секрет хранит в файле, доступном лишь вам.
