# Cloudflare Worker

[English](CLOUDFLARE.md) · **Русский**

Worker — это крошечная программа, которая работает в сети Cloudflare. `tg-proxy` общается с ней по HTTPS/WebSocket, а TCP-соединение с Telegram Worker открывает уже *со стороны Cloudflare*. Для цензора вы просто разговариваете с Cloudflare.

Зачем это нужно:

- это единственный маршрут, который достаёт до **всех** дата-центров Telegram (DC1–DC5, DC203); собственный WebSocket-шлюз Telegram обслуживает только DC2 и DC4;
- он **ваш**: никакого стороннего пула;
- он **бесплатный** и не требует доменного имени;
- один Worker обслуживает и вас, и всех ваших друзей.

Worker из [`cloudflare/worker.js`](../cloudflare/worker.js) не является открытым ретранслятором: он отклоняет любой адрес вне опубликованных диапазонов Telegram.

## Настройка (около 5 минут)

1. Создайте бесплатный аккаунт на <https://dash.cloudflare.com> и подтвердите почту.
2. Откройте **Compute (Workers) → Workers & Pages → Create → Start with Hello World → Deploy**.
3. Нажмите **Edit code**, удалите всё, вставьте содержимое [`cloudflare/worker.js`](../cloudflare/worker.js) и нажмите **Deploy**.
4. Скопируйте адрес Worker'а, примерно `tg-relay.your-name.workers.dev`.
5. Запустите прокси с ним:

   ```bash
   tg-proxy --cfproxy-worker-domain tg-relay.your-name.workers.dev
   ```

6. Проверьте: `tg-proxy --check --cfproxy-worker-domain tg-relay.your-name.workers.dev` должен показать ✔ по каждому дата-центру в разделе *Cloudflare Worker*.

> **Панель управления не открывается из моей сети.** Некоторые сети замедляют `cloudflare.com` / `workers.dev`. Панель нужна один раз, для развёртывания: сделайте настройку из сети, где она открывается, или через любой VPN. Дальше Worker работает без вас.

## Использование

```bash
# один Worker
tg-proxy --cfproxy-worker-domain tg-relay.your-name.workers.dev

# несколько, чтобы распределить нагрузку (повторите флаг или через запятую)
tg-proxy --cfproxy-worker-domain a.workers.dev,b.workers.dev

# или переменной окружения
TG_PROXY_WORKER_DOMAINS=tg-relay.your-name.workers.dev tg-proxy
```

Worker пробуется сразу после прямого маршрута и раньше общего пула доменов. Друзьям передавайте только **адрес**: они подставят его в ту же опцию.

## Лимиты и приватность

- У бесплатного плана есть суточный лимит запросов (на момент написания Cloudflare указывает 100 000 на аккаунт; актуальные лимиты смотрите у них). Личный прокси открывает умеренное число соединений, так что вы вряд ли приблизитесь к нему. Если лимит Worker'а исчерпан, запросы к нему завершаются ошибкой, а `tg-proxy` переходит к следующему маршруту.
- Cloudflare видит, *что* вы подключаетесь и сколько данных передаёте, но не содержимое. Ваши сообщения остаются зашифрованными MTProto между приложением Telegram и серверами Telegram.
- `--no-secure` заставляет `tg-proxy` ходить к Worker'у по обычному HTTP на порт 80. Это может ускорить установку соединения, когда мешает именно TLS к Cloudflare, но раскрывает адрес Worker'а и путь запроса всем на маршруте. Используйте, только если больше ничего не помогает.

## Свой домен вместо Worker'а (домены за Cloudflare)

Если у вас есть домен, его можно подключить к Cloudflare и использовать маршрут 3 с ним вместо общего пула.

1. Добавьте домен в Cloudflare (<https://developers.cloudflare.com/dns/zone-setups/full-setup/setup/>).
2. **SSL/TLS → Overview**: режим **Flexible**.
3. **DNS → Records**: добавьте эти `A`-записи **с включённым проксированием** (оранжевое облако):

   | Имя | IPv4 |
   |---|---|
   | `kws1` | `149.154.175.50` |
   | `kws2` | `149.154.167.51` |
   | `kws3` | `149.154.175.100` |
   | `kws4` | `149.154.167.91` |
   | `kws5` | `149.154.171.5` |
   | `kws203` | `91.105.192.100` |

4. Запустите `tg-proxy --cfproxy-domain your-domain.com` и подтвердите через `--check`.

Так настраивается оригинальный проект `tg-ws-proxy`; проверить этот вариант от начала до конца здесь не удалось, поэтому опирайтесь на `--check`. У бесплатных доменов Cloudflare ограничивает число одновременных WebSocket-соединений, так что Worker обычно надёжнее.

## Если что-то не так

| Симптом | Причина / решение |
|---|---|
| `--check` показывает `HTTP 403` для Worker'а | Адрес назначения вне диапазонов Telegram. Убедитесь, что развернули неизменённый `worker.js`. |
| `HTTP 404` | Неверный путь или вы открыли адрес в браузере; `tg-proxy` использует `/apiws`. |
| `timeout` на всех пробах Worker'а | Cloudflare недоступен из этой сети или в адресе опечатка. Попробуйте `--upstream-socks5`, а в крайнем случае `--no-secure`. |
| `HTTP 429` / ошибка 1015 | Worker или домен упёрся в лимит Cloudflare. Добавьте второй Worker. |
